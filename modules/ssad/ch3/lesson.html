Symmetric cryptography (Cryptographie symétrique)

↑ contents
In plain words

In Caesar’s day the secret was the method itself. Today every algorithm is published and attacked by everyone, so the only secret left is a short key. In symmetric cryptography one key (or two keys easily computed from each other) both locks and unlocks, so sender and receiver must agree on it before any message is sent.

  • Symmetric cryptography (cryptographie à clé secrète)one shared key for encrypting and decrypting. Example: both sides hold 133457799BBCDFF1.
  • Secret key (clé secrète)the only value that must stay hidden. Example: a 56-bit DES key.
  • Sender / receiver (émetteur / destinataire)the two parties who must share the key first. Example: Alice and Bob.
  • Block cipher (chiffrement par bloc)scrambles a whole chunk (often 64 bits) at once. Example: DES, AES.
  • Stream cipher (chiffrement en continu, à flot)scrambles bit by bit with a generated key stream. Example: RC4.
  • Round (tour, ronde, itération)one repetition of the same scrambling step. Example: DES repeats it 16 times.
Worked example
  • Caesar era: the method (“shift by 3”) was the secret. Modern era: DES, AES, IDEA are public; only the key is secret.
  • Key (hex): 133457799BBCDFF1 (64 bits, of which 56 are real key bits).
  • Plaintext ATTACK!! = 8 characters = 64 bits = one DES block = 41545441434B2121.
  • Encrypt with DES: CE529E61192F25FA. Decrypt with the same key: 41545441434B2121 = ATTACK!!.

Block or stream? (Chiffrement par bloc ou en continu)

↑ contents
In plain words

A block cipher cuts the message into fixed-size chunks and scrambles each chunk as a whole. A stream cipher scrambles one bit at a time by XOR-ing it with a stream of key bits. Both lean on XOR, the “add without carrying” operation.

  • Block (bloc)a fixed-size chunk of the message: 64 bits for DES, 128 for AES. Example: ATTACK!! is one 8-byte block.
  • XOR (exclusive or) (ou exclusif, addition modulo 2)1 when the two bits differ, 0 when equal. Example: 1011 ⊕ 0110 = 1101.
  • Keystream (flux de clé)a bit sequence derived from the key, XORed with the message. Example: 01101101.
  • Padding (bourrage)filler bytes that complete the last block (not named in the course, but always needed). Example: 02 02 after “T DAWN”.
  • Mode of operation (mode de chiffrement)the recipe for using a block cipher on a long message. Example: ECB, CBC, OFB, CFB.
Worked example
  • XOR key property: apply the same bits twice and you are back. 10110010 ⊕ 01101101 = 11011111, then 11011111 ⊕ 01101101 = 10110010.
  • Padding: ATTACK AT DAWN is 14 bytes. Blocks are 8 bytes, so it becomes ATTACK A | T DAWN + two bytes 02 02.

Stream ciphers and RC4 (Chiffrement en continu et RC4)

↑ contents
In plain words

A stream cipher cuts nothing into blocks. A generator turns the key into a long, unpredictable bit sequence (the keystream) and each message bit is XORed with the next keystream bit. The whole security rests on the quality of that generator.

  • Keystream generator (générateur pseudo-aléatoire)produces the key bits from the key. Example: RC4 produces one byte per step.
  • RC4 (RC4)a stream cipher with a variable key length, usually 128 bits. Example: key Key.
  • State (état)RC4 keeps a shuffled list S of the numbers 0…255 and swaps two entries at every step. Example: a mini version with 8 slots.
  • Synchronous error behaviour (non-propagation des erreurs)one wrong ciphertext bit gives one wrong plaintext bit, nothing more. Example: why phones use stream ciphers.
  • Keystream reuse (réutilisation du flux)using the same keystream twice is fatal: the key cancels out. Example below.
Worked example
  • Bits: m = 10110010, s = 01101101, c = m ⊕ s = 11011111. Decrypt: c ⊕ s = 10110010.
  • Mini RC4 (8 slots, key 1 2 3, for illustration only). Key setup gives S = 2 0 1 3 7 5 6 4. First keystream values: 1 3 2 3 1.
  • Encrypt symbols 5 1 6 2 7 ⊕ keystream = 4 2 4 1 6 (3-bit values). Decrypting returns 5 1 6 2 7.
  • Real RC4, key Key, plaintext Plaintext: ciphertext BBF316E8D940AF0AD3 (matches the published test vector).
  • Reuse danger: RC4(ATTACK) ⊕ RC4(DEFEND) with the same key = ATTACK ⊕ DEFEND = 051112040D0F. The keystream vanished, so an attacker can work on the two plaintexts directly.

ECB: Electronic Code Book (Mode livre de codage électronique)

↑ contents
In plain words

The most obvious way to use a block cipher: encrypt every block on its own with the same key. It is simple, and blocks are independent. The catch: the same plaintext block always becomes the same ciphertext block, so patterns show through and a spy collecting pairs can build a codebook without ever learning the key.

  • ECB (livre de codage électronique)each block is encrypted independently: cᵢ = E_K(mᵢ). Example: two equal blocks give two equal ciphertexts.
  • Codebook attack (construction d’un livre de codage)collect known (plaintext, ciphertext) pairs and look blocks up. Example: a header that is always ATTACK!!.
  • Known plaintext (texte clair connu)the attacker already knows some plaintext and sees its ciphertext. Example: a fixed file header.
Worked example

CBC: Cipher Block Chaining (Chaînage de blocs)

↑ contents
In plain words

Chaining fixes ECB’s weakness: before a block is encrypted it is XORed with the previous ciphertext block. The first block has no predecessor, so a random starting value, the IV, plays that role. Equal plaintext blocks no longer give equal ciphertext blocks.

  • CBC (chaînage de blocs)cᵢ = E_K(mᵢ ⊕ cᵢ₋₁). Example: block 3 is mixed with c₂ before encryption.
  • IV (initialization vector) (vecteur d’initialisation)the random “block 0”, sent in the clear; it does not need to be secret. Example: 0001020304050607.
  • Feedback (rétroaction)a previous result is reused as input to the next step. Example: cᵢ₋₁ feeds block i.
  • Error propagation (propagation d’erreur)how far one corrupted bit spreads. Example: in CBC it reaches two blocks.

OFB and CFB (Modes à rétroaction de sortie et de chiffrement)

↑ contents
In plain words

These two modes turn a block cipher into a stream cipher. The block cipher is used only to make keystream, and the message is XORed with it. OFB feeds its own output back to make the next key block; CFB feeds back the previous ciphertext block.

  • OFB (output feedback) (rétroaction de sortie)z₀ = IV, zᵢ = E_K(zᵢ₋₁), cᵢ = mᵢ ⊕ zᵢ. Example: the key blocks never depend on the message.
  • CFB (cipher feedback) (rétroaction du chiffré)z₀ = IV, zᵢ = E_K(cᵢ₋₁), cᵢ = mᵢ ⊕ zᵢ. Example: the key block depends on the last ciphertext block.
  • Encryption-only (chiffrement seul)both modes decrypt with E_K, never D_K. Example: the same circuit does both jobs.
  • Use (utilisation)the course says secure phones: very long key stream mixed with a data stream. Example: OFB for noisy lines.

Confusion, diffusion and Feistel (Confusion, diffusion et réseau de Feistel)

↑ contents
In plain words

Good ciphers mix two ideas from Shannon. Confusion hides how the key relates to the ciphertext (non-linear substitutions). Diffusion spreads each plaintext bit over many ciphertext bits (permutations). Repeating both for several rounds is an iterated product cipher. A Feistel network is a clever skeleton that lets the same circuit encrypt and decrypt.

  • Confusion (confusion)make the ciphertext–key relation complicated, with substitutions. Example: DES S-boxes.
  • Diffusion (diffusion)make every output bit depend on all input bits, with permutations. Example: one flipped bit reaches half the output.
  • Avalanche effect (effet d’avalanche)a tiny change in the plaintext changes about half the ciphertext. Example: chart on the right.
  • Feistel network (réseau de Feistel)split into halves L and R; each round: L′ = R, R′ = L ⊕ F(k, R). Example: DES.
  • Iterated cipher (système itéré)N identical rounds, each with its own subkey. Example: N = 16 for DES.
Worked example

DES in detail (Le DES (Data Encryption Algorithm))

↑ contents
In plain words

DES scrambles a 64-bit block through 16 identical rounds. Each round splits the block into a left half L and a right half R, runs R through a function F that depends on a 48-bit subkey, and XORs the result into L before swapping. Decrypting is the same machine with the subkeys in reverse order.

  • DES / DEA (Data Encryption Algorithm)IBM’s LUCIFER, modified; 64-bit block, 56-bit key, 16 rounds. Example: 0123456789ABCDEF → 85E813540F0AB405.
  • Initial permutation IP (permutation initiale)a fixed reordering of the 64 input bits, undone at the end by IP⁻¹. Example: bit 58 moves to position 1.
  • Expansion E (fonction d’expansion)turns 32 bits into 48 by repeating 16 of them. Example: bit 32 is copied before bit 1.
  • S-box (boîte de substitution)eight tables, each turning 6 bits into 4. The only non-linear step. Example: S₁(011011) = 5.
  • Permutation P (permutation P)shuffles the 32 S-box output bits. Example: bit 16 goes to position 1.
  • Round function F (fonction ronde)F(k,R) = P( S( E(R) ⊕ k ) ). Example: round 1 below.
Worked example
  • Key 133457799BBCDFF1, plaintext 0123456789ABCDEF.
  • After IP: L₀ = CC00CCFF, R₀ = F0AAF0AA.
  • Round 1 subkey k₁ (8 groups of 6 bits): 000110 110000 001011 101111 111111 000111 000001 110010.
  • E(R₀) (48 bits): 011110 100001 010101 010101 011110 100001 010101 010101.
  • E(R₀) ⊕ k₁: 011000 010001 011110 111010 100001 100110 010100 100111.
  • S-box outputs (8 × 4 bits): 0101 1100 1000 0010 1011 0101 1001 0111.
  • After P: 234AA9BB. R₁ = L₀ ⊕ P(…) = EF4A6544 and L₁ = R₀ = F0AAF0AA.
  • S-box lookup by hand: the first 6-bit group is 011000. Row = first and last bit = 00 = 0, column = middle four bits = 1100 = 12, so S₁ gives 5.
  • After round 16, swap halves and apply IP⁻¹: ciphertext 85E813540F0AB405. Running the same code with the subkeys reversed gives back 0123456789ABCDEF.

DES keys, strength and 3DES (Sous-clés, sécurité et triple DES)

↑ contents
In plain words

The 64-bit DES key hides 8 parity bits, so only 56 bits matter. A key schedule turns them into sixteen 48-bit subkeys. The algorithm itself has held up well: its one real weakness is that 2⁵⁶ keys can be tried by brute force. The fix is to chain DES several times.

  • Parity bit (bit de détection d’erreur)bits 8, 16, …, 64 make every key byte hold an odd number of 1s. Example: 13 = 00010011 has three 1s.
  • Key schedule (génération des sous-clés)PC-1 drops parity and splits the key; rotations and PC-2 give each kᵢ. Example: k₁ = 1B02EFFC7072.
  • Exhaustive search (recherche exhaustive)try every key. Example: 2⁵⁶ ≈ 7.2 × 10¹⁶ keys.
  • 2DES and 3DES (double et triple DES)DES applied twice or three times with different keys. Example: y = E_k3(D_k2(E_k1(x))).
  • Differential / linear attacks (attaques différentielles / linéaires)clever statistical attacks. Example: DES’s S-boxes were chosen to resist them.
Worked example
  • Parity check on the key: byte 13 = 0001001 + parity bit 1 → three 1s, odd. All eight bytes of 133457799BBCDFF1 pass.
  • Rotation amounts for rounds 1–16: 1 1 2 2 2 2 2 2 1 2 2 2 2 2 2 1, total 28 = 28, so after round 16 the halves are back at C₀ and D₀ (checked).
  • Time to try every key at a very optimistic 10¹² keys per second:
Key bitsTime
56 (DES)about 20 hours

  • 2DES looks like 2¹¹² keys, but a meet-in-the-middle attack stores E(x) for every k₁, then tries D(y) for every k₂ and looks for a match: about 2⁵⁷ operations instead of 2¹¹². It needs a few known plaintext/ciphertext pairs and a huge table.
  • Triple DES check: with k₁ = k₂ = k₃ the middle D cancels the first E and 3DES gives 85E813540F0AB405, identical to single DES. With a different middle key it is 055152350CD7A4BB (k₂ = 0E329232EA6D0D73).

AES (AES, l’alternative au DES)

↑ contents
In plain words

AES works on 16 bytes at a time, laid out as a 4 × 4 grid called the state. Each round does four simple things to that grid: substitute the bytes, shift the rows, mix the columns, add the round key. The round is repeated 10, 12 or 14 times depending on the key size. It is fast, simple and has no practical attack.

  • AES (Advanced Encryption Standard) (standard de chiffrement avancé)128-bit block, 128/192/256-bit key. Example: 0001…0F key, 0011…FF block.
  • State (état)the 16 bytes arranged in 4 rows × 4 columns, filled column by column. Example: bytes A…P below.
  • SubBytes (substitution d’octets)every byte goes through the same S-box (inverse in GF(2⁸), then a fixed bit mix). Example: 53 → ED.
  • ShiftRows (décalage cyclique des lignes)row r rotates left by r positions. Example: row 1: F J N B.
  • MixColumns (multiplication des colonnes)each column is multiplied by a fixed polynomial over GF(2⁸). Example: DB 13 53 45 → 8E 4D A1 BC.
  • AddRoundKey (ajout de la clé de tour)XOR the state with the round subkey. Example: first step of encryption.
  • Galois field GF(2⁸) (corps de Galois à 256 éléments)a byte treated as a number where addition is XOR and multiplication wraps with a fixed polynomial. Example: 57 • 13 = FE.
Worked example
  • GF(2⁸) arithmetic: addition is XOR (57 ⊕ 83 = D4). “Multiply by 2” shifts left and, if a bit falls off, XORs 1B: 57 → AE and 80 → 1B. Hence 57 • 13 = 57 ⊕ (57•2) ⊕ (57•2•2•2•2) = FE.
  • S-box: S(00) = 63, S(53) = ED (53 inverted in GF(2⁸) is CA, then the fixed bit mix).
  • MixColumns on DB 13 53 45 gives 8E 4D A1 BC.
  • Full round 1 on the standard test block 00112233445566778899AABBCCDDEEFF with key 000102030405060708090A0B0C0D0E0F:
  • start (block ⊕ key): 00102030405060708090A0B0C0D0E0F0

  • ShiftRows: 6353E08C0960E104CD70B751BACAD0E7
  • MixColumns: 5F72641557F5BC92F7BE3B291DB9F91A

IDEA (IDEA (International Data Encryption Algorithm))

↑ contents
In plain words

IDEA also chops data into 64-bit blocks and runs 8 identical rounds, but with a 128-bit key and no S-boxes. Its trick is to mix three different kinds of arithmetic that do not play well together algebraically: XOR, addition modulo 2¹⁶ and multiplication modulo 2¹⁶+1.

  • IDEA (International Data Encryption Algorithm)Lai and Massey, Zurich, 1990 (first PES, then IPES after differential cryptanalysis appeared, then IDEA). Example: 64-bit block, 128-bit key.
  • Sub-block (sous-bloc)a 16-bit piece; the block is X₁ X₂ X₃ X₄. Example: 0000 0001 0002 0003.
  • Three operations (trois opérations)⊕ XOR, ⊞ addition mod 2¹⁶, ⊙ multiplication mod 2¹⁶+1 (0 stands for 2¹⁶). Example: 8000 ⊙ 2 = 0000.
  • Subkeys (sous-clés)52 sixteen-bit values: 6 per round × 8 rounds, plus 4 for the output step. Example: Z₁ … Z₅₂.
  • Weak key (clé faible)a special key that makes encryption weaker. Example: keys with long zero runs; chance 1 in 2⁹⁶.
Worked example
  • ⊙ example: 0x8000 = 32768, and 32768 × 2 = 65536 = 2¹⁶ ≡ −1 (mod 65537). The value 2¹⁶ is written 0, so 8000 ⊙ 0002 = 0000 (checked). Also 0 ⊙ 0 = 2¹⁶ × 2¹⁶ mod (2¹⁶+1) = 1. And FFFF ⊞ 0001 = 0000.
  • Key schedule: split the 128-bit key into eight 16-bit subkeys, rotate the whole key 25 bits left, split again, and so on until 52 subkeys. Key 0001 0002 … 0008 gives first 0001 0002 0003 0004 0005 0006 0007 0008, then 0400 0600 0800 0A00 0C00 0E00 1000 0200.
  • Encrypt 0000 0001 0002 0003 with that key: 11FB ED2B 0198 6DE5 (matches the published IDEA test vector).
  • Decrypt: run the same circuit with inverse subkeys (multiplicative inverses mod 2¹⁶+1 and additive inverses mod 2¹⁶, in reverse order). Checked: it returns 0000 0001 0002 0003.
  • Brute force: 2¹²⁸ keys. At the course’s 13 750 blocks per second that is 7.8 × 10²⁶ years on a 486 (recomputed), and still about 7.8 × 10¹⁴ years if a machine were 10¹² times faster. Probability of drawing one of the known weak keys: 1 / 2⁹⁶ = 79228162514264337593543950336.

Everything in the chapter on one page: which algorithm, how big, what shape, and how the modes differ.

Notes on the original text
  • DES round function. The course writes F(k,R) = π(S(E(R)) ⊕ kᵢ). The key is XORed before the S-boxes: F = π(S(E(R) ⊕ kᵢ)), as the course’s own step (ii) says.
  • π tables. The first row of π ends in “12”; it should be 2. The π⁻¹ table lost its formatting in the PDF (digits split across lines) and its third row starts “38 5” instead of “38 6”.
  • CBC error spreading. The course says an error propagates through the rest of the text. Measured here: one flipped ciphertext bit garbles one block and flips one bit in the next, then everything decrypts correctly again.
  • Feistel and F. The course says Feistel systems use a non-linear bijection F. Feistel’s point is that F does not need to be invertible (see the toy example, where F(5,1) = F(5,7)).
  • 2DES / 3DES figures. “2⁵⁶² = 2¹²⁸” should read 2⁵⁶ × 2⁵⁶ = 2¹¹² keys, and the known attack needs about 2⁵⁷ operations (the printed “265” looks like a lost exponent). The usual figures for 3DES are a 2¹⁶⁸ key space and about 2¹¹² for the best generic attack, not 2¹²⁸ and 2⁴⁶.
  • Dates and status. The course says DES is still considered safe and AES is not yet widespread. In practice DES keys were found by brute force in 1998–99 and DES was retired; AES became the standard in 2001 and is everywhere. IDEA’s patent is also no longer an obstacle.
  • AES description. “Nb = 4, 6 or 8 columns” belongs to Rijndael; the AES block is always 128 bits (Nb = 4). The number of rounds (10, 12, 14) depends on the key size. The list under “4 transformations” contains six items; the four are SubBytes, ShiftRows, MixColumns, AddRoundKey, and the last round omits MixColumns.
  • IDEA steps A1–A14. As printed, A5 = A1 ⊕ A3 would XOR X₁⊙Z₁ with X₂⊞Z₂, whereas IDEA pairs it with X₃⊞Z₃. The wording of the final swap is also hard to follow. This primer uses the standard design, which reproduces the official test vector. The text also says six subkeys per round; the full total is 52. “7.8*1026” and “296” are 7.8 × 10²⁶ and 2⁹⁶ (both numbers check out).
  • Speed claims. The course says stream ciphers are very fast, and also that block ciphers are usually faster. Which one wins depends on the algorithm and the hardware.
