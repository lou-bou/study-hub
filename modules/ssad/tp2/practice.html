Warm-up: the tool (prise en main)

Two-minute reflexes. Unless a task says otherwise, message.txt is the course file: the line Hello Prof Nacer and a newline (17 bytes). Make it with printf 'Hello Prof Nacer\n' > message.txt.

A1List the ciphersWarm-up target 1 min0:00

In OpenSSL 3 (Ubuntu 24.04), which command lists the cipher names enc accepts?

Show solution

openssl list -cipher-commands (or openssl enc -list). The one-word form is the 1.x spelling and gives Invalid command 'list-cipher-commands'. Openssl with a capital is not found at all.

A2Count random bytesWarm-up target 2 min0:00

Without guessing, run them and count: (1) how many characters does openssl rand -hex 16 print (newline not counted)? (2) what size in bytes is k.bin after openssl rand -out k.bin 32?

Show solution

(1) 32: 16 bytes, two hex characters each. (2) 32 bytes: rand counts in bytes, never bits. Check with openssl rand -hex 16 | tr -d '\n' | wc -c and wc -c k.bin.

What text is hidden in U1NBRCBUUDI=?

B1Decrypt the professor's messageStandard target 3 min0:00

The professor sends this file, encrypted with AES-256-CBC, -pbkdf2, as base64 text, password nacer2026. What does it say?

cat > b1.b64 <<'EOF'
U2FsdGVkX18lHaOTt+SzebC3fEZMIQ71NOB4oL0XJ3+bEHf+ZoN5K618Afm7Hh/R
EOF
Show solution

openssl enc -aes-256-cbc -pbkdf2 -base64 -d -in b1.b64 -pass pass:nacer2026 → RDV salle 12 a 10h

B2Round trip and sizeStandard target 3 min0:00

Encrypt message.txt with AES-256-CBC and -pbkdf2, without -base64, into m.enc; decrypt it into back.txt; check cmp message.txt back.txt prints nothing. How many bytes is m.enc?

Show solution
openssl enc -aes-256-cbc -pbkdf2 -in message.txt -out m.enc -pass pass:tp2
openssl enc -aes-256-cbc -pbkdf2 -d -in m.enc -out back.txt -pass pass:tp2
cmp message.txt back.txt && echo same
wc -c m.enc

48 = 8 (Salted__) + 8 (salt) + 32 (17 bytes padded to two 16-byte blocks).

B3Password file loopStandard target 3 min0:00

Make a password file with openssl rand -hex 32 > k.hex, encrypt message.txt with it, decrypt with it. How many bytes is k.hex? And which pair of options reads the password from the file?

Show solution

65 bytes: 64 hex characters + a newline (ignored by enc). -kfile and -pass file: both read the first line, so they mix fine. -k k.hex would use the 5 letters k.hex as password (it still "works" on both sides, but the file is useless). -pass k.hex is an error: -pass needs pass:, file:, env:...

openssl enc -aes-256-cbc -pbkdf2 -in message.txt -out m.enc -kfile k.hex
openssl enc -aes-256-cbc -pbkdf2 -d -in m.enc -pass file:k.hex

B5The iteration countCompetition target 4 min0:00

AES-256-CBC, -pbkdf2, base64, password usthb. With the default settings you get bad decrypt. The sender's note says "200 000". Plaintext?

cat > b5.b64 <<'EOF'
U2FsdGVkX1/SnekjptHk/q6vZBRYeAomOcjEENang7NAfz7/xup1sPc4jnZX+86p
EOF

A teammate runs this and gets the output shown. What is the fix?

$ openssl enc -aes-256-cc -base64 -in message.txt -out crypted -pass pass:tp2
enc: Unknown cipher: aes-256-cc
enc: Use -help for summary.
Show solution

"Unknown cipher" = the name is wrong. The handout's -aes-256-cc is a typo for -aes-256-cbc.

C2Fix the commandStandard target 2 min0:00

A teammate runs this and gets the output shown. What is the fix?

$ openssl enc -aes-256-cbc -pbkdf2 -base64 -in crypted -out clear.txt -pass pass:tp2; head -c 24 clear.txt
U2FsdGVkX1/yiYHWEya0iXSI
Show solution

No error and the "decrypted" file starts with U2FsdGVkX1 (= Salted__): it is a fresh ciphertext. Add -d.

C3Fix the commandStandard target 1 min0:00

A teammate runs this and gets the output shown. What is the fix?

$ openssl enc -aes-256-cbc -pbkdf2 -d -in crypted -pass pass:tp2
bad magic number
Show solution

"bad magic number" = no Salted__ at the start of what was read: the file is base64 text. Add -base64.

C4Fix the commandStandard target 2 min0:00

A teammate runs this and gets the output shown. What is the fix?

$ openssl enc -aes-256-cbc -base64 -d -in crypted -pass pass:tp2
*** WARNING : deprecated key derivation used.
Using -iter or -pbkdf2 would be better.
bad decrypt
Show solution

The warning says the old derivation is in use on this side; the sender used -pbkdf2, so the keys differ and the padding check fails. Add -pbkdf2.

C5Fix the commandStandard target 2 min0:00

A teammate runs this and gets the output shown. What is the fix?

$ openssl enc -aes-256-cbc -pbkdf2 -d -in c2.bin -k cle.key
bad decrypt
Show solution

c2.bin was encrypted with -kfile cle.key. -k cle.key uses the 7 letters cle.key as password, so the key is wrong.

C6Fix the commandStandard target 1 min0:00

A teammate runs this and gets the output shown. What is the fix?

$ openssl enc –aes-256-cbc -in message.txt -pass pass:tp2
enc: Use -help for summary.
Show solution

The long dash from the PDF is a different character; OpenSSL sees an unknown argument and prints its usage line. Retype every - by hand.

C7Fix the commandStandard target 2 min0:00

A teammate runs this and gets the output shown. What is the fix?

$ openssl enc -des-cbc -pbkdf2 -in message.txt -out d.bin -pass pass:tp2
Error setting cipher DES-CBC
Show solution

OpenSSL 3 moved DES, Blowfish, RC4... to the legacy provider. openssl enc -des-cbc -provider legacy -provider default -pbkdf2 -in message.txt -out d.bin -pass pass:tp2 works (40 bytes).

C8Fix the commandStandard target 2 min0:00

A teammate runs this and gets the output shown. What is the fix?

$ openssl enc -aes-256-ctr -pbkdf2 -d -in cctr -pass pass:wrong -out junk.txt; echo "exit code $?"
exit code 0
Show solution

Only padded modes (CBC, ECB) can say bad decrypt. Stream modes (CTR, chacha20) decrypt to garbage silently. Always cat the result.

C9Fix the commandStandard target 1 min0:00

A teammate runs this and gets the output shown. What is the fix?

$ openssl -out key 1024
Invalid command '-out'; type "help" for a list.
Show solution

The handout's line has no command. openssl rand -hex 32 > key is the better form for a password file.

D

Identify the cipher (identifier l'algorithme)

↑ contents

Clues: the U2FsdGVkX1 start, the output size, and which cipher decrypts without an error.

D1Sizes give it awayStandard target 2 min0:00

Three teams encrypted the same 17-byte message.txt with -pbkdf2 (no base64). Their files are 48, 40 and 33 bytes. Which cipher made each?

Show solution

Header 16 bytes in all cases. AES blocks are 16 bytes: 17 → 32, total 48. Triple DES blocks are 8 bytes: 17 → 24, total 40. CTR is a stream mode: 17 → 17, total 33.

D2Which cipher?Competition target 5 min0:00

Password m1bigdata, -pbkdf2, base64. The cipher is one of aes-128-cbc, aes-256-cbc, camellia-256-cbc, aria-256-cbc. Which one, and what is the message?

cat > d2.b64 <<'EOF'
U2FsdGVkX182irNsPDFoIdFrw+BpSV4fDQhRuTHkqIQ=
EOF
Show solution

Try them in a loop; the wrong ones fail with bad decrypt:

for c in aes-128-cbc aes-256-cbc camellia-256-cbc aria-256-cbc; do
  echo "== $c"; openssl enc -$c -pbkdf2 -base64 -d -in d2.b64 -pass pass:m1bigdata 2>/dev/null
done

Only camellia-256-cbc gives text: camellia gagne. (Checked: the three others all fail.)

D3What U2FsdGVkX1 tells youWarm-up target 1 min0:00

A base64 ciphertext starts with U2FsdGVkX1. What do you learn?

Show solution

echo U2FsdGVkX1 | openssl base64 -d starts with Salted__. The cipher name is never stored: you must know it or try candidates (D2).

F

RSA: sign, verify, encrypt (RSA)

↑ contents

Make a key pair first: openssl genrsa -out priv.pem 2048 then openssl rsa -in priv.pem -pubout -out pub.pem.

F1Sign and verifyStandard target 3 min0:00

Sign message.txt with SHA-256 and your private key, then verify with the public key. What exactly is printed on success?

Show solution
openssl dgst -sha256 -sign priv.pem -out message.sig message.txt
openssl dgst -sha256 -verify pub.pem -signature message.sig message.txt

→ Verified OK

F2Tampered fileStandard target 2 min0:00

Change one character of message.txt (add a dot), verify the same signature again. What is printed, and what exit code does echo $? show?

Show solution

Verification failure, exit code 1 (plus error lines). One changed byte changes the hash, so the signature no longer matches.

F3How much can RSA encrypt?Competition target 3 min0:00

With a 2048-bit key and pkeyutl -encrypt (default padding), what is the largest input in bytes? Test with head -c N /dev/urandom > b.bin.

Show solution

245 = 256 − 11 bytes of PKCS#1 padding. 245 works, 246 gives data too large for key size (both tested). For bigger files: encrypt a random password with RSA and the file with enc (hybrid, lesson section 12).

F4Wrong key fileStandard target 1 min0:00

openssl dgst -sha256 -verify priv.pem -signature message.sig message.txt prints Could not read public key from priv.pem. Fix?

Show solution

-verify expects a public key. -prverify priv.pem also works since the public key is inside the private one.

F5Hybrid hand-offCompetition target 6 min0:00

Bob gives you bob_pub.pem. Send him report.pdf so that only he can read it, using a random AES password. Write the commands, then let your teammate play Bob and decrypt.

Show solution
openssl rand -hex 32 > pw.txt
openssl enc -aes-256-cbc -pbkdf2 -in report.pdf -out report.enc -pass file:pw.txt
openssl pkeyutl -encrypt -pubin -inkey bob_pub.pem -in pw.txt -out pw.enc
# send report.enc and pw.enc. Bob:
openssl pkeyutl -decrypt -inkey bob_priv.pem -in pw.enc -out pw.txt

G3A tiny CACompetition target 6 min0:00

Create a CA, a CSR for vm2, sign it with the CA, verify it. Which file does -CAcreateserial create, and what does the final verify print?

Show solution
openssl req -x509 -newkey rsa:2048 -nodes -keyout ca.key -out ca.crt -days 365 -subj '/CN=SSAD Test CA'
openssl req -new -newkey rsa:2048 -nodes -keyout vm2.key -out vm2.csr -subj '/CN=vm2'
openssl x509 -req -in vm2.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out vm2.crt -days 30
openssl verify -CAfile ca.crt vm2.crt

ca.srl (the serial number counter) and vm2.crt: OK.
