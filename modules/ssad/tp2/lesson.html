What OpenSSL is (Qu'est-ce qu'OpenSSL)

↑ contents
In plain words

OpenSSL is a free toolbox for cryptography (the science of hiding and protecting data). It comes in two parts:

a library, code that other programs call: web servers, curl and many others use it to protect their connections;

a command-line tool, the program openssl you type in a terminal. It can encrypt files, make keys, compute fingerprints, make certificates and test secure connections. TP 2 uses this tool.

The name comes from SSL, the old protocol that protects a network connection. Its modern version is called TLS. People still say "SSL" out of habit.

  • protocol (protocole)A fixed list of messages two programs send each other, in a fixed order, so they understand each other.
  • SSL (Secure Sockets Layer)Netscape's protocol from the 1990s to protect a TCP connection. Every SSL version is now broken and switched off.
  • TLS (Transport Layer Security)The successor of SSL, run by the IETF (the group that writes Internet standards). TLS 1.2 and 1.3 protect every HTTPS site today.
  • TCP/IPThe network layers that carry bytes from one machine to another. They hide nothing: anyone on the path can read the bytes.
  • fingerprint (empreinte)A short code computed from a file (a hash). Change one letter of the file and the fingerprint changes completely.SHA-256, MD5

The handshake, then the talk (poignée de main, puis communication)

↑ contents
In plain words

Before any secret data travels, client and server hold a short conversation called the handshake. In it they:

1. say hello and agree on which algorithms to use;
2. the server shows its certificate, a kind of ID card, so the client knows who it is talking to;
3. both sides compute the same fresh secret key, the session key, without ever sending it.

Then comes the communication step: every chunk of data is encrypted with the session key and carries a tag that shows whether anyone changed it on the way.

  • handshake (poignée de main)The opening messages of a TLS connection, before any real data.
  • cipher suite (suite cryptographique)The set of algorithms both sides agree on, written as one name.TLS_AES_256_GCM_SHA384 = encrypt with AES-256 in GCM mode, hash with SHA-384
  • certificate (certificat)A file holding a public key and a name, signed by an authority that vouches the key belongs to that name (section 13).
  • key exchange (échange de clés)Each side mixes its own secret number with a public value from the other side. Both get the same result; a spy who saw only the public values cannot.X25519
  • session key (clé de session)The shared secret the key exchange produced. It lives only for this connection.
  • record (enregistrement)One encrypted chunk of data in the communication step, with its integrity tag.
  • s_server / s_clientTwo OpenSSL commands for testing TLS by hand. s_server is a tiny server that waits for a connection; s_client is a tiny client that connects to it. Once connected, what you type on one side appears on the other, encrypted on the way.
  • portA door number on a machine (1 to 65535). A server listens on one port; a client must knock on the same one. HTTPS uses 443; our tests use 4433.

Typing commands and getting help (commandes et aide)

↑ contents
In plain words

You talk to OpenSSL in a terminal. Every line has the same shape: openssl <command> <options>. The command picks the tool (enc to encrypt, dgst for fingerprints, genrsa for RSA keys...). The options say how, each starting with one dash.

You never need to remember everything: openssl help lists the commands, and openssl enc -help lists the options of one command.

In OpenSSL 3, typing openssl alone just prints the command list and gives you back the normal prompt. The old OpenSSL> prompt of the handout is gone, so always write openssl in front of every command.

  • shell (interpréteur de commandes)The program that reads what you type in the terminal (on Ubuntu, bash).
  • prompt (invite)The sign the shell prints when it waits for you, usually $. You do not type it.
  • command (commande)The word right after openssl.enc, dgst, rand, genrsa, req, s_client
  • option (option)A setting starting with -. Some need a value: -in message.txt.
  • man page (page de manuel)The full manual of a command: man openssl-enc. Press q to leave it.

Encrypt a file with enc (chiffrer un fichier)

↑ contents
In plain words

openssl enc takes a file and a password and writes a scrambled copy. Only someone with the same password can get the original back. Because the same secret locks and unlocks, this is called symmetric encryption.

AES-256 needs a key of exactly 32 bytes that look random. A password like tp2 is neither, so enc first stretches it into a key with a recipe called PBKDF2. It also adds 8 random bytes, the salt, so the same password gives a different key every time.

The output starts with the word Salted__ and the salt, so that decrypting later can redo the same stretch.

  • plaintext / ciphertext (texte clair / chiffré)The readable file before encryption / the scrambled file after.
  • AES (Advanced Encryption Standard)The standard symmetric cipher. It works on blocks of 16 bytes; -aes-256 means a 256-bit (32-byte) key.
  • CBC (chaînage de blocs)A mode: each block is mixed with the previous encrypted block before being encrypted, so equal blocks do not give equal output.
  • padding (bourrage)Bytes added so the message fills whole 16-byte blocks. Decryption checks them and removes them.
  • salt (sel)Random bytes mixed into the password before stretching it. Stored in clear at the start of the file.
  • PBKDF2 (dérivation de clé)The stretch: hash password + salt thousands of times (10 000 by default). Slow on purpose, so guessing passwords is slow too. Turned on by -pbkdf2.
  • IV (vecteur d'initialisation)16 extra bytes that start the CBC chain. Comes out of the same stretch.
  • base64A way to write any bytes with 64 printable characters, so the result can be shown, copied and pasted. -base64 (or -a).
Worked example

The course example. The file message.txt contains the line Hello Prof Nacer and a newline. Encrypt it with AES-256-CBC, password tp2, and write the result as text:

$ printf 'Hello Prof Nacer\n' > message.txt
$ wc -c message.txt

$ openssl enc -aes-256-cbc -pbkdf2 -base64 -in message.txt -out crypted -pass pass:tp2
$ cat crypted

5

Where the password comes from (le mot de passe)

↑ contents
In plain words

The handout calls it a "private key" but for enc it is simply a password: any line of text both sides know. You can type it, write it in the command, or keep it in a file.

A good password file is long and random. openssl rand makes random bytes; with -hex it writes them as readable characters, which is what you want in a password file.

When enc reads a password from a file, it takes only the first line, without its newline. That one rule explains two traps of the handout: a binary rand file, and an RSA key made by genrsa.

  • random bytes (octets aléatoires)Bytes nobody can predict. openssl rand N makes N of them.
  • byte vs bit (octet / bit)1 byte = 8 bits. rand counts in bytes: rand 32 = 256 bits.
  • hex (hexadécimal)Each byte written as two characters 0-9 A-F. rand -hex 32 prints 64 characters.
  • -k / -kfileOld options: -k WORD = the password is WORD; -kfile FILE = the password is the first line of FILE.
  • -passThe modern form: pass:WORD, file:FILE, env:VAR (from a variable), stdin.

Decrypt, and read the errors (déchiffrer)

↑ contents
In plain words

To decrypt, repeat the encrypt line, add -d, and give the encrypted file as input. Everything else must be exactly what the sender used: the cipher name, -pbkdf2 (and -iter if any), -base64, and the password.

OpenSSL almost never tells you which one is wrong. Its usual complaint, bad decrypt, only means "the padding at the end came out wrong", which happens with any mismatch. So learn the few messages below by heart: in a timed TP they save minutes.

  • -d (déchiffrer)Decrypt. Without it enc encrypts (that is -e, the default).
  • bad decryptThe last block's padding is wrong after decryption: wrong password, cipher, -pbkdf2 or -iter.
  • bad magic numberThe input does not start with Salted__: usually a -base64 mismatch.
  • exit code (code de retour)A number every command leaves behind: 0 = success. See it with echo $? right after the command.

Cheatsheet · RSA keys, encrypt, sign (RSA)

↑ contents
In plain words

RSA is asymmetric: two keys that go together. The private key stays on your machine; the public key is made from it and can be given to anyone. What one key locks, only the other unlocks.

RSA can only encrypt a few hundred bytes, so in practice it protects a short secret (like an enc password) and AES does the bulk.

  • key pair (bi-clé)A private key (priv.pem) and the public key derived from it (pub.pem).
  • PEMText format for keys and certificates: base64 between -----BEGIN ...----- lines.
  • signature (signature)A value made with a private key over a file's hash. Anyone with the public key can check it.
  • pkeyutlThe v3 command for RSA encrypt/decrypt/sign. The old rsautl is deprecated.

Cheatsheet · certificates and a small CA (certificats X.509)

↑ contents
In plain words

A certificate glues a name (like CN = vm2) to a public key, and carries the signature of whoever vouches for that link. If you sign it yourself it is self-signed: fine for a test, but a client will warn. If a CA you trust signs it, the client accepts it.

  • X.509The standard certificate format used by TLS.
  • CSR (demande de certificat)Certificate Signing Request: your public key + name, sent to a CA to be signed.
  • CA (autorité de certification)Whoever signs certificates. Here, a test CA you create in two commands.
  • subject / issuer (sujet / émetteur)Whose certificate it is / who signed it. Equal for a self-signed certificate.
  • CN (Common Name)The name in the certificate, usually the machine's name.

Make

# self-signed cert + new key, no passphrase (-nodes)

$ openssl req -new -key priv.pem -out vm2.csr -subj '/CN=vm2'

Notes on the original course
  • Handout 2 header: "Couse" should read Course.
  • Handout 1 writes "TSL" several times; the protocol is TLS.
  • "openssl" then "OpenSSL> q": OpenSSL 3 has no interactive prompt. Typing openssl alone prints the command list and returns; write openssl before every command. Lines written $rand ..., $genrsa ..., $ enc-aes ... therefore need openssl in front.
  • openssl list-cipher-commands is the 1.x spelling; OpenSSL 3 answers "Invalid command". Use openssl list -cipher-commands or openssl enc -list. $ help alone runs the shell's own help, not OpenSSL's: use openssl help, and openssl enc -help for Enc –help.
  • enc-aes is not a command ("Invalid command 'enc-aes'"): it needs a space and a full cipher name, e.g. enc -aes-256-cbc. The same example also decrypts mestest.txt into mescrypt.txt, the file names the wrong way round.
  • -aes-256-cc should be -aes-256-cbc ("Unknown cipher"). -aes-256-cbc-base64 is missing a space before -base64.
  • Openssl –out key 1024 is missing the subcommand (openssl rand -out key 1024) and starts with a capital O, which Linux does not find.
  • Dashes: the handouts print long dashes and spaces (– in, – out, - <algo>). Copied as is they fail; options are one ASCII hyphen glued to the name: -in, -out, -aes-256-cbc.
  • "output.txt: File saving the decrypted message" in the encryption part: it is the encrypted message.
  • -k cle.key: -k takes the password itself, so the password becomes the 7 letters cle.key and the file is never read (checked in section 5). To use the file, write -kfile cle.key or -pass file:cle.key.
  • rand -out cle.key 2048 "using the specified number of bits": the size is in bytes (2048 bytes = 16 384 bits). The file is also binary, and enc reads a password file only up to its first newline byte, which can leave a short or empty password. Use openssl rand -hex 32 > cle.key.
  • Case 2, genrsa as the enc key: enc cannot use an RSA key as a key. Through -kfile it reads only the first line, -----BEGIN PRIVATE KEY-----, which is the same for every key: a file encrypted with one genrsa key decrypts with any other (checked in section 5). Use rand for passwords; RSA keys go with pkeyutl and dgst -sign. Also, 1024-bit RSA is too short today: use 2048.
  • "private key" for the enc password: in symmetric encryption it is a secret key (or simply a password). "Private key" means the secret half of an RSA pair.
  • No -pbkdf2 in any handout command. OpenSSL 3 then warns "deprecated key derivation used" because the old method hashes the password only once. Add -pbkdf2 to both the encrypt and the decrypt line; leaving it on one side only gives "bad decrypt".
  • DES, IDEA, RC2, RC4, Blowfish (listed as examples) are switched off by default in OpenSSL 3 ("unsupported"); they need -provider legacy -provider default. Triple DES (-des3) and AES work. MD5 is broken for security; prefer SHA-256.
  • "Data are exchanged in compressed, encrypted and signed format": TLS compression was dropped after the 2012 CRIME attack and TLS 1.3 removed it. Each record is protected by an integrity tag (MAC/AEAD), not a signature; signatures are used once, during the handshake.
