Core vocabulary (Vocabulaire de base)

↑ contents
In plain words

Every term below fits one picture: a readable message goes in, a key scrambles it, and an unreadable message comes out. Only someone with the key can reverse it.

  • Cryptology (cryptologie)the science of secret messages. It covers cryptography and cryptanalysis.
  • Cryptography (cryptographie)making a message unreadable to everyone except the receiver. Example: HELLO becomes KHOOR.
  • Cryptanalysis (cryptanalyse)reading a message without the key. Example: guessing the shift of a Caesar message.
  • Plaintext (texte clair)the original, readable message. Example: HELLO.
  • Ciphertext (texte chiffré, cryptogramme)the scrambled message. Example: KHOOR.
  • Key (clé)the secret value (a number or a word) used to scramble and unscramble. Example: shift 3, or the word KEY.
  • Encryption / decryption (chiffrement / déchiffrement)scrambling and unscrambling with the key. Example: HELLO → KHOOR → HELLO.
  • Code breaking (décryptage)recovering the plaintext without the key. Not the same as decryption. Example: trying all 26 shifts.
  • Cipher (chiffre)the method that replaces or moves letters. Example: Caesar, Vigenère.
  • Bigram (bigramme)a group of two letters. Example: TH, ES.
  • Cryptosystem (cryptosystème)an encryption algorithm plus a decryption algorithm. Example: Caesar with key 3.
Worked example
  • Caesar with key 3: encrypt HELLO → KHOOR. Decrypt by shifting back 3: KHOOR → HELLO.
  • Formal definition: a cryptosystem is a set (P, C, K, E, D): plaintexts, ciphertexts, keys, encryption functions, decryption functions. The one rule that matters: decrypting with the right key always gives back the original message.
  • Restricted use (usage restreint): the algorithm itself is secret, e.g. a homemade scrambling method kept hidden. Weak: once it leaks, everything is lost.
  • General use (usage général): the algorithm is public and only the key is secret, e.g. Caesar (everyone knows "shift", only k is hidden). This is the modern approach.

Two families of ciphers (Deux familles de chiffrements)

↑ contents
In plain words

Every classical cipher does one of two things: it swaps letters for other letters, or it shuffles the letters it already has. The first is substitution, the second is transposition.

  • Substitution (substitution)letters are replaced, positions stay. Example: CAT → FDW.
  • Transposition (transposition)letters are reordered, letters stay. Example: CAT → TAC.
  • Monoalphabetic (mono-alphabétique)one letter always becomes the same other letter. Example: Caesar.
  • Polyalphabetic (poly-alphabétique)the same letter can become different letters. Example: Vigenère.
  • Polygraphic (polygrammique)letters are replaced in blocks, such as pairs. Example: Playfair, Hill.
Worked example
  • Substitution, each letter +3: CAT → FDW.
  • Transposition, reversed: CAT → TAC.
  • Monoalphabetic: AA → DD. Polyalphabetic (Vigenère, key KE): AA → KE, since A+K = K and A+E = E.
  • Polygraphic: Playfair turns the pair HE into CF as one unit.
  • Transposition keeps letter counts: OLLEH still has two L's, like HELLO. That is why frequency analysis does not help against it.

Atbash and Caesar (Atbash et César)

↑ contents
In plain words

Both ciphers replace each letter by another in a fixed way. Atbash flips the alphabet, Caesar slides it. The same letter in always gives the same letter out, so both are monoalphabetic.

  • Atbash (Atbash)reverse the alphabet: A↔Z, B↔Y, and so on. No key.
  • Caesar cipher (chiffrement de César)shift every letter forward by k. Number letters A=0 … Z=25. Encrypt: C = (L + k) mod 26. Decrypt: L = (C − k) mod 26.
  • Modulo (modulo)mod 26 means "wrap around after Z": take the remainder after dividing by 26. Example: 27 mod 26 = 1.
  • Brute force (force brute)try every possible key. Caesar has only 26.
  • Frequency analysis (analyse des fréquences)count letters in the ciphertext and match the most common one to E. First described by Al-Kindi (about 873).
Worked example
  • Atbash: HELLO → SVOOL.
  • Caesar with k = 3, letter by letter:
letterHELLO
number74111114
+ 3107141417
cipherKHOOR
  • Brute force on KHOOR: try each shift until a word appears.

  • Frequency analysis: in a long ciphertext the most frequent letter is H. English uses E most, so k = H − E = 7 − 4 = 3.

Affine cipher (Chiffrement affine)

↑ contents
In plain words

Affine is Caesar with one extra step: multiply each letter's number by a, then add b. The catch is that a must share no factor with 26, otherwise two letters collide and you cannot decrypt.

  • Affine cipher (chiffrement affine)key = a pair (a, b). Encrypt: C = (a·L + b) mod 26. Decrypt: L = a⁻¹·(C − b) mod 26.
  • Coprime (premiers entre eux)sharing no divisor except 1, written gcd(a, 26) = 1 (gcd = PGCD, greatest common divisor).
  • Modular inverse (inverse modulaire)the number a⁻¹ with a·a⁻¹ mod 26 = 1. You need it to decrypt.
  • Key space (espace des clés)12 valid values of a × 26 values of b = 312 keys. With a = 1 it is plain Caesar.
Worked example
  • Why coprime: with a = 2, b = 3, A (0) → 3 and N (13) → 2·13 + 3 = 29, and 29 mod 26 = 3. Two letters, one image: impossible to decrypt.
  • Encrypt HI with (5, 8): H = 7 → 5·7 + 8 = 43, and 43 mod 26 = 17 = R. I = 8 → 5·8 + 8 = 48, and 48 mod 26 = 22 = W. Result: RW.
  • Decrypt R: a⁻¹ = 21 because 5 × 21 = 105 = 4·26 + 1. Then 21 × (17 − 8) = 189, and 189 mod 26 = 7 = H.
  • Break it: suppose frequency analysis suggests E → C and T → Z. Then 4a + b ≡ 2 and 19a + b ≡ 25. Subtract: 15a ≡ 23 (mod 26). Since 15⁻¹ = 7, a = 23·7 = 161 ≡ 5, and b = 2 − 20 ≡ 8. Key found: (5, 8).

Vigenère cipher (Chiffre de Vigenère)

↑ contents
In plain words

Vigenère is Caesar with a moving shift. A keyword decides the shift for each letter, so the same plain letter can come out different each time. That defeats simple frequency analysis.

  • Vigenère cipher (chiffrement de Vigenère)polyalphabetic. Each key letter is a shift: A = 0, B = 1, … Z = 25. The key repeats to cover the message.
  • Keyword (mot-clé)the repeating key. Example: KEY gives shifts 10, 4, 24.
  • One-time pad (masque jetable)a random key as long as the message, used once. Unbreakable, but sharing so many keys safely is hard.
  • Kasiski test (test de Kasiski)find chunks that repeat in the ciphertext. The key length divides the distance between repeats.
  • Key length (longueur de la clé)once known, the text splits into that many Caesar ciphers.
Worked example
plainATTACK
keyKEYKEY
shift1042410424
cipherKXRKGI
  • Encrypt ATTACK with key KEY → KXRKGI. Decrypting subtracts the same shifts.
  • Kasiski: one chunk repeats 20 apart, so the key length divides 20: {2, 4, 5, 10, 20}. Another repeats 15 apart: {3, 5, 15}. The only common value is 5.
  • Then split the ciphertext into 5 groups (letters 1, 6, 11, …; letters 2, 7, 12, …; and so on). Each group is a plain Caesar cipher, so frequency analysis cracks each one.

Playfair cipher (Chiffre de Playfair)

↑ contents
In plain words

Playfair encrypts letters two at a time using a 5×5 grid built from a keyword. Because pairs are scrambled instead of single letters, simple letter counts no longer work.

  • Playfair cipher (chiffre de Playfair)polygraphic. Write the keyword without repeated letters, then the rest of the alphabet. I and J share a cell.
  • Rectangle rule (règle du rectangle)pair on different row and column: take the other two corners, each staying on its own row.
  • Same row (même ligne)take the letter to the right of each (wrap around).
  • Same column (même colonne)take the letter below each (wrap around).
  • Double letter (lettre doublée)insert an X between them (LL → LX L). An odd last letter gets an X.
  • Known plaintext (texte clair connu)an attacker who has both texts recovers the grid quickly.
Worked example
  • Grid for key MONARCHY: rows MONAR, CHYBD, EFGIK, LPQST, UVWXZ.
  • Encrypt HELP: split into HE LP. HE is a rectangle → CF. LP is on one row, so move right → PQ. Result: CFPQ.
  • Column case: MC → move down → CE.
  • Double letters: BALLOON → pairs BA LX LO ON → IBSUPMNA.
  • Decrypt with the same rules backwards (left and up). Break it with the most frequent bigrams (TH, ES, …).

Hill cipher (Chiffrement de Hill)

↑ contents
In plain words

Hill encrypts blocks of letters with a matrix. Each pair of letters becomes two numbers, gets multiplied by a 2×2 key matrix, and wraps around mod 26. Each output letter depends on both input letters, which hides single-letter patterns.

  • Hill cipher (chiffrement de Hill)polygraphic, using matrix multiplication (C1, C2) = K × (L1, L2) mod 26.
  • Determinant (déterminant)for [[a, b], [c, d]] it is ad − bc. The key is valid only if gcd(det, 26) = 1.
  • Inverse matrix (matrice inverse)K⁻¹ = det⁻¹ · [[d, −b], [−c, a]] mod 26 decrypts.
  • Extended Euclidean algorithm (algorithme d'Euclide étendu)finds a modular inverse: run the gcd steps down, then substitute back up.
  • Probable-word attack (attaque par mot probable)guess a likely word in the message and test it against the ciphertext.
Worked example
  • Key K = [[3, 3], [2, 5]]: det = 3·5 − 3·2 = 9 and gcd(9, 26) = 1, so K is valid.
  • Encrypt HELP → HE = (7, 4): C1 = 3·7 + 3·4 = 33 → 7 = H; C2 = 2·7 + 5·4 = 34 → 8 = I.
  • LP = (11, 15): C1 = 33 + 45 = 78 → 0 = A; C2 = 22 + 75 = 97 → 19 = T. Result: HIAT.
  • Inverse of the determinant by extended Euclid: 26 = 2·9 + 8 and 9 = 1·8 + 1. Back up: 1 = 9 − 8 = 9 − (26 − 2·9) = 3·9 − 26. So 9⁻¹ = 3 (check: 9·3 = 27 ≡ 1).
  • K⁻¹ = 3 · [[5, −3], [−2, 3]] = [[15, 17], [20, 9]] mod 26. Test on HI = (7, 8): 15·7 + 17·8 = 241 → 7 = H, and 20·7 + 9·8 = 212 → 4 = E. We get HE back.

Transposition ciphers (Chiffrement par transposition)

↑ contents
In plain words

Transposition keeps every letter but shuffles the order, like an anagram. The classic trick: write the message in rows, then read it out by columns. The letters never change, so counting them tells the attacker nothing.

  • Scytale (scytale)ancient Greek device: a strip wrapped around a rod, message written along the rod, unreadable once unwrapped.
  • Simple columnar transposition (transposition simple par colonnes)write in rows under n columns, read column by column.
  • Complex columnar transposition (transposition complexe par colonnes)same grid, but the columns are read in the alphabetical order of a keyword.
  • Anagram (anagramme)the same letters in a different order.
Worked example
  • Scytale: HELPMENOW written as rows HELP, MENO, W. Reading down the columns: HMW EE LN PO → HMWEELNPO.
  • Simple columnar, MEETATNOON with n = 4: columns MAO, ETN, EN, TO → MAOETNENTO.
  • Complex columnar, key ZEBRA (ranks Z=5, E=3, B=2, R=4, A=1), message WEAREDISCOVERED: read columns in order 1 to 5: EOD ASR EIE RCE WDV → EODASREIERCEWDV.
  • Decrypt: rebuild the same grid (when the length does not divide evenly, the first columns are one letter taller), fill it by columns, read by rows.
  • Break it: slide two paper strips of the ciphertext against each other until neighbouring columns form likely bigrams (QU, ES, …).

Cheat sheet and history (Récapitulatif et histoire)

↑ contents
In plain words

Classical ciphers protected secrets for centuries, but computers break them in moments. That is why the next chapter moves to modern cryptography.

Timeline, oldest first
  1. about 1900 BCNon-standard Egyptian hieroglyphs: earliest known written cryptography.
  2. about 500 BCAtbash (Hebrews). The scytale follows (Greeks, about 487 BC).
  3. about 50 BCCaesar cipher.
  4. about 873Al-Kindi describes frequency analysis.
  5. 1467Alberti invents the first polyalphabetic cipher.
  6. 1585Vigenère cipher, long believed unbreakable.
  7. 1854Wheatstone invents Playfair; Babbage breaks Vigenère.
  8. 1917Vernam invents the one-time pad.
  9. 1918 to 1945Enigma, a rotor machine, broken by Rejewski, then by Turing at Bletchley Park.
  10. 1976DES; Diffie and Hellman introduce public-key cryptography.
  11. 1977RSA.
  12. 2000AES (Rijndael) replaces DES.
