1

What is scheduling? (L’ordonnancement)

↑ contents
In plain words

Scheduling means deciding which task runs on which machine, and when, so that a goal (finish early, pay few penalties) is as good as possible.

  • Task (tâche, travail, job)A unit of work to carry out.a part to build, a program to run, a surgery
  • Resource / machine (ressource, machine)Whatever executes tasks: a material, financial or human means.a machine tool, a processor, a surgeon
  • Constraint (contrainte)A limit imposed by the environment.one task at a time on a machine
  • Objective (objectif, critère d’optimisation)The quantity we want to minimise (or maximise).the time at which everything is finished
  • Deterministic problem (problème déterministe)All task parameters are known in advance.durations 3, 5, 2, 1, 2 are given
  • Classical hypotheses (hypothèses classiques)(a) a machine processes at most one task at a time; (b) a task is processed by at most one machine at a time.
  • Gantt diagram (diagramme de Gantt)One row per machine, time on the horizontal axis; each block is a task. Gaps are idle time (temps mort).
Production piece → machine toolComputing program → processor Construction plumbing → plumberHospital operation → surgeon Restaurant meal → cookResearch project → researcher
Worked example · Example 1 of the course

Build 5 pieces T1…T5 on 3 identical machines. Durations: 3, 5, 2, 1, 2. A task cannot be interrupted once started. Finish as early as possible.

The schedule ends at time 5. Of the 3 × 5 = 15 machine-time units, 13 are used (3+5+2+1+2) and 2 are idle on M3.

Why can’t we do better than 5?

T2 alone lasts 5 and cannot be cut, so the end can never be before 5. Our schedule reaches 5, so it is optimal.

Why it is hard: with 10 tasks there are already 10! = 3,628,800 possible orders. Scheduling problems are combinatorial (problèmes combinatoires), so we need efficient algorithms rather than trying everything.

2

Machines (Caractérisation des machines)

↑ contents
In plain words

Either every machine can do every task (parallel), or each machine has its own specialty and tasks are cut into steps (dedicated).

We write T = {T1,…,Tn} for the n tasks and M = {M1,…,Mm} for the m machines.

Parallel machines (machines parallèles)

They run the same treatments, so any task fits any machine. The three types differ by speed. Let pij be the time machine Mj needs for task Ti.

  • Identical (machines identiques)All speeds are equal: pij = pi.3 identical CPUs; a task with p = 6 takes 6 on each
  • Uniform (machines uniformes)Each machine has a constant speed factor bj: pij = pi / bj. The standard time pi corresponds to bj = 1.pi = 6 on machines with b = 1, 2, 3 takes 6, 3, 2
  • Unrelated (machines générales)Speed depends on the task: the pij are arbitrary.a GPU is fast on one task and slow on another (table below)

Dedicated machines (machines spécialisées ou dédiées)

Each machine is specialised. Each task Ti is split into a finite number of operations Oi1,…,Oiki, each possibly needing a different machine.

  • Flow shop (atelier à cheminement unique, atelier en ligne)Every task goes through all machines, in the same order.trucks: unload at D, then load at C (Example 4)
  • Open shop (atelier à cheminement libre)Every task goes through all machines, but no order is imposed.a patient needs a blood test and an X-ray, in either order
  • Job shop (atelier à cheminements multiples)Each task has its own subset of machines and its own order, fixed in advance.J1 uses M1 then M3; J2 uses M2, M1, M3
3

Describing tasks (Description des tâches)

↑ contents
In plain words

Each task carries a few numbers (how long, when available, when due, how important) plus rules about interrupting it and about what must come first.

  • Processing time (durée de traitement) pijTime machine Mj needs to finish Ti. See section 2 for identical and uniform cases.
  • Release date (date d’arrivée, de disponibilité) riWhen Ti becomes ready. If all are equal we set ri = 0.r = 3: the part arrives at time 3 and cannot start earlier
  • Due date (date échue, fin au plus tard) diTarget end. Finishing later is allowed but counts as lateness.
  • Deadline (date limite, absolue) d̃iHard limit: finishing after it is not acceptable.
  • Weight (poids) wiRelative priority: a penalty, a profit, etc.late armoire costs 400 DA/day, late chair set 100 DA/day
  • Preemption (préemption)Preemptive mode: a task can be stopped at any time at no cost and finished later, possibly on another machine. Otherwise non-preemptive (sans préemption).a long computation paused for a short urgent one
  • Precedence constraint (contrainte de précédence) Ti < TjTi must be finished before Tj starts. If some tasks are comparable the set is dependent (dépendantes), otherwise independent (indépendantes).paint only after the wall is built
  • Precedence graph (graphe de précédence)Directed graph: vertices are tasks, arcs are precedence constraints.
Due date vs deadline

Due date = target (miss it and you pay). Deadline = wall (miss it and the schedule is invalid).

A schedule (Ordonnancement)

↑ contents
In plain words

A schedule gives every task a machine and a time slot. It is feasible (admissible, réalisable) if it breaks none of four rules.

1 at each instant, each machine runs at most one task and each task is on at most one machine 2 task Ti only runs in [ri, +∞[ 3 if Ti < Tj, then Tj starts only after Ti ends 4 non-preemptive: no task is interrupted (otherwise only finitely many preemptions)
Worked example · a feasible schedule for the 10-task instance

Spot-checks of the rules:

  • T6 starts at 3. Its predecessors T2 (ends 3), T3 (ends 1) and T4 (ends 3) are done. ✓ rule 3
  • T8 starts at 4, exactly its release date r8 = 4. ✓ rule 2
  • T9 starts at 9, the moment T7 ends. ✓ rule 3
  • No two blocks overlap on the same row. ✓ rule 1

A program confirmed all 10 tasks satisfy every rule.

5

Optimality criteria (Critères d’optimalité)

↑ contents
In plain words

First measure each task in a given schedule (when it ends, how long it stayed, how late it is). Then squash these into one number, the criterion, that we try to minimise.

Per-task measures

  • Completion time (date d’achèvement) ciWhen Ti finishes.
  • Flow time (durée de flot, de séjour) fi = ci − riWaiting time plus processing time.arrives at 3, ends at 7: f = 4
  • Lateness (tardiveté, retard algébrique) li = ci − diCan be negative (early).due 3, ends 1: l = −2
  • Tardiness (retard) ti = max{li, 0}Lateness with early finishes counted as 0.due 6, ends 9: t = 3
  • Tardy indicator (indicateur de retard) uiui = 1 if ci > di, else 0.

The four main criteria

  • Makespan (longueur de l’ordonnancement)Cmax = max ci. When everything is finished.
  • Mean flow time (temps de flot moyen)F = (1/n) Σ fi. Average time a task spends in the system.
  • Maximum lateness (grande tardiveté)Lmax = max li. The worst lateness.
  • Number of tardy jobs (nombre de tâches en retard)NT = Σ ui. How many tasks end after their due date.

Why are 11 and 3 the best possible?

T5 cannot start before r5 = 3, lasts 4, then T7 (2) and T9 (2) must follow in a chain. So T9 ends at 3+4+2+2 = 11 at the earliest, giving Cmax ≥ 11 and l9 ≥ 11 − 8 = 3, hence Lmax ≥ 3. Both are reached.

For F and NT the best values (34/10 and 2) were found by an exact solver; the course states NT = 2 as optimal and our solver agrees.

Takeaway: one schedule can be optimal for one criterion and not for another. Criteria pull in different directions.

Other criteria used

In plain words

Every criterion is built from the per-task values ci, fi, li, ti, ui in one of three ways: max (worst task), mean (add up, divide by n), or weighted mean (multiply each by its weight wi, add up, divide by Σwi). The bar means “mean”, the subscript w means “weighted”.

Relations between criteria (Remark 1)

1) Cw, Fw, Lw are equivalent, and so are C, F, L: they differ by a constant, since fi = ci − ri and the ri never change. Check: Σc − Σr = 61 − 18 = 43 = Σf.
2) In general Cmax, Fmax, Lmax are not equivalent.
3) A schedule optimal for Lmax is optimal for Tmax, because Tmax = max{Lmax, 0}. (The course leaves the proofs as exercises.)

6

Classification α | β | γ (Classification)

↑ contents
In plain words

A three-slot code names any scheduling problem: α = which machines, β = which task constraints, γ = which goal. The symbol ∅ means “write nothing”.

α

Resources (ressources) = α1α2

  • α1: 1 one machine, P identical, Q uniform, R unrelated, O open shop, F flow shop, J job shop
  • α2 (used only when α1 ≠ 1): ∅ = number of machines is variable; k = exactly k machines (a positive integer)

β

Constraints (contraintes) = β1…β5

  • β1: ∅ no preemption, pmtn preemption allowed
  • β2: ∅ independent, prec any precedence, tree, chains (other kinds of directed graphs are possible)
  • β3: ∅ all ri = 0, ri release dates, not all identical
  • β4: ∅ arbitrary, not all equal; pi = p all equal (also pi = 1; bounded times p̲ ≤ pi ≤ p̄ appear in the reduction graph)
  • β5: ∅ none (or implied by the criterion), di due dates, d̃i deadlines

γ

Criterion (critère) to minimise

  • Cmax, C, Cw, Tmax, T, Tw, Lmax, U, Uw, …
  • γ = − means: just find a feasible solution

Decoding the course examples

P | ∅ | Cmax
  • α = P: parallel identical machines, variable number
  • β = ∅: independent, non-interruptible tasks, arbitrary times, all release dates 0
  • γ: finish everything as early as possible
O3 | pmtn, ri | F
  • α: open shop with 3 machines
  • β: operations are preemptible, with arbitrary release dates
  • γ: minimise the mean flow time
1 | ri, pi = 1 | Lmax
  • α: a single machine
  • β: unit processing times, arbitrary release dates (and due dates, needed by Lmax), no interruption
  • γ: minimise the maximum lateness
Q2 | tree | Cmax
  • α: 2 uniform parallel machines
  • β: dependent tasks whose precedences form a tree (arborescence), non-interruptible
  • γ: minimise the end date

Reductions (Réduction entre problèmes d’ordonnancement)

↑ contents
In plain words

An arrow A → B means A is a special case of B: a method that solves B also solves A after a cheap (polynomial) transformation. So hardness travels up the arrows: if A is hard, B is at least as hard.

Machines. One machine is a special case of k identical ones (k = 1); identical is uniform with all bj = 1; uniform is unrelated with pij = pi/bj. Flow shop is a special case of job shop.

Constraints. No constraint ⊂ chains ⊂ tree ⊂ general precedence. No release dates ⊂ release dates (all 0). Equal times ⊂ bounded times ⊂ arbitrary times. Preemption and no-preemption are not comparable.

Criteria.

  • Σfi reduces to Σwifi with wi = 1So C, T, U reduce to Cw, Tw, Uw.
  • Cmax, C, Cw reduce to Lmax, T, Tw with di = 0If every due date is 0, then li = ci and ti = ci.
  • Lmax reduces to T and ULeft as an exercise in the course.
Worked example · the di = 0 trick

Take the schedule of section 1 (c = 3, 5, 2, 5, 4 for T1…T5) and set every due date to 0. Then li = ci, so Lmax = max{3,5,2,5,4} = 5 = Cmax. Minimising Lmax on this modified instance is exactly minimising Cmax on the original.

Three real-looking problems, each solved, each checked: tasks with precedence, tasks with penalties, and a two-step shop.

Example 2 · Nine programs on two processors  (P2|prec|Cmax)

Durations T1…T9: 3, 2, 2, 5, 3, 4, 1, 3, 4. Precedences are in the graph. Minimise the total time.

Result: Cmax = 15. The solver finds nothing shorter.

Why 15 is optimal

The chain T1 → T4 → T6 → T8 must run one after another: 3 + 5 + 4 + 3 = 15. The total work 27 split over 2 machines would only give 13.5, so here the chain, not the machine count, is the bottleneck.
