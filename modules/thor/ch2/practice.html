A1Which rule solves 1|ri|Cmax?Warm-up
Show solution

ERD. Theorem 1: sort by release date, start each task at max(previous end, ri). O(n log n).

A2Which rule solves 1||Cw?Warm-up
Show solution

WSPT (Theorem 2, Smith's rule). SPT is the special case where all wi = 1.

A3What about 1|set-up|Cmax?Warm-up
Show solution

Hard. Minimising total setup is a shortest Hamiltonian path in a complete directed graph. The course uses a greedy heuristic.

A4Reading the reductions diagramStandard

Arrows in the diagram: pi=1 → ∅ → ri (A → B means A is a special case of B).

1. 1||C (box ∅) is easy. What can you say about 1|pi=1|C?

2. 1|ri|C is hard. What can you say about 1||C?

Show solution
  1. Easy. pi=1 → ∅ and ∅ is easy: easy flows against the arrow.
  2. Nothing. Hardness flows along the arrow, from ∅ to ri, not back. (1||C is in fact easy, by SPT.)

D2Beat the heuristic by waitingChallenge

Same data as D1. Schedule the order T2, T3, T1, T4, each task as early as possible (the machine stays idle from 0 to 1).

Why does it beat the heuristic?

Show solution

T2 1→2, T3 2→4, T1 4→8, T4 8→11. Σ C = 2+4+8+11 = 25, C = 6.25 < 6.5. This is the best of all 24 orders. The heuristic never idles on purpose, so it started the long T1 at 0 and made T2 and T3 wait behind it.

D3WSPT exchange: compute the changeChallenge

In some order, Ti (p=3, w=1) runs immediately before Tj (p=2, w=4). Swapping two neighbours changes Σ wkCk by wipj − wjpi.

Should you swap them?

Show solution

Change = 1·2 − 4·3 = −10: the swap lowers Σ wkCk by 10, so yes. Check with the ratios: pi/wi = 3 > pj/wj = 0.5, so WSPT puts Tj first.

Method (§12): ns(i) = arrows leaving Ti. Fill positions 5, 4, …, 1: each time take the smallest-numbered task with ns = 0, then subtract 1 from ns of every task with an arrow into it.
Show solution

Start: ns = (1, 2, 1, 0, 0).

  • Position 5: ns = 0 for T4, T5 → T4. T2 loses one: ns(2) = 1.
  • Position 4: T5. T3 loses one: ns(3) = 0.
  • Position 3: T3. T1 and T2 lose one: both 0.
  • Position 2: T1. Position 1: T2.

Order T2, T1, T3, T5, T4, every arrow points right. Cmax = 2 + 4 + 1 + 3 + 2 = 12 (any valid order gives 12).

Method (§13): for each arrow Ti → Tj in order: rj := max(rj, ri + 1). Then run by new r, as early as possible. A block = tasks back to back without a gap.
Show solution
