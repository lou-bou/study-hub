Scheduling on a single machine

One machine, n tasks, one task at a time. Which order finishes soonest, or keeps the average completion time low? Part 1 asks when everything finishes. Part 2 adds due dates, deadlines and delivery times. Part 3 adds rules like “this task only after that one”. Some versions fall to a simple sorting rule, others are hard and need a quick rule of thumb or a search tree. (Ordonnancement sur une seule machine)

1

Reductions between problems (réductions, transformations polynomiales)

↑ contents
In plain words

Many problems are special cases of others: unit durations are just durations that happen to equal 1. If you can solve the general problem, you can solve the special one. So easy travels against the arrows and hard travels along them.

  • easy (polynomial) (polynomial)A method exists whose work grows like n, n log n or n² with the number of tasks n: fast even for big n. O(n²) (complexité) means “about n × n steps”.
  • hard (NP-hard) (NP-difficile)Nobody knows a fast exact method: the known ones try a number of orders that explodes as n grows. We then use a search tree or a heuristic.
  • polynomial reduction (transformation polynomiale)A → B: every instance of A can be rewritten as an instance of B in polynomial time.
  • ∅ (empty β field)No extra constraint: all tasks ready at 0, any durations, no preemption.
  • release date (date de disponibilité) riTask Ti cannot start before ri.
  • preemption (préemption) pmtnA task may be interrupted and resumed later.
  • identical / unit durations (durées identiques / unitaires)pi = p for all tasks, or pi = 1.
The rule. For an arrow A → B:
  • B easy (polynomial) ⇒ A easy.
  • A hard (NP-hard) ⇒ B hard.
  • The converse statements tell you nothing.
Worked example
  1. Easy flows down. 1||C (box ∅) is solved by SPT (§5). The arrow pi=1 → ∅ then says 1|pi=1|C is easy too. Check: with unit tasks every order gives completions 1, 2, …, n, so for n = 4, C = (1+2+3+4)/4 = 2.5.
  2. Hard flows up. 1|ri|C is hard (§6). The arrow ∅ → ri points into it, so this says nothing about ∅, which is indeed easy.
  3. Chains. pi=1 → ∅ → ri: arrows compose, so the unit problem is also a special case of the release-date problem.
2

1||Cmax and 1|pmtn|Cmax (sans dates de disponibilité)

↑ contents
In plain words

Everything is ready at time 0. If the machine never stops, it finishes exactly when it has done all the work. The order does not matter, and cutting tasks into pieces does not help either: the total work is the same.

  • start time (date de début) si, completion time (date de fin) Ci = si + pi
  • makespan (durée totale) Cmax = max CiWhen the last task finishes.
  • left-justified, no idle time (calé à gauche, sans temps mort)Each task starts the moment the previous one ends.
Cmax = p1 + p2 + … + pn computed in O(n)
The algorithm, line by line
  1. 1s1 := 0 ; C1 := s1 + p1The first task starts at time 0. Its end, the completion time (date de fin) C1, is its start (date de début) s1 plus its duration p1.
  2. 2for i := 2 to n doThen take the other tasks one by one, in the order given.
  3. 3 si := C(i−1)Each task starts the very moment the previous one ends: no gap (sans temps mort, calé à gauche).
  4. 4 Ci := si + piIt ends after its own duration.
  5. 5Cmax := CnThe makespan (durée totale) Cmax is the end of the last task.

In simple terms: put the tasks one after the other with no gap. The end is always the total work, whatever the order.

1|ri|Cmax (avec dates de disponibilité)

↑ contents
In plain words

Now tasks arrive over time. Serve them in order of arrival. The machine then only waits when nothing has arrived yet, and that kind of wait no order can avoid.

  • ERD rule (ordre croissant des dates de disponibilité)Earliest Release Date first: sort tasks by ri.
  • forced idle time (temps mort)The machine is free but no task is released yet.
  • Theorem 1 (Théorème 1)ERD solves 1|ri|Cmax in O(n log n) (the cost of sorting).
The algorithm, line by line
  1. 1sort the tasks by increasing riERD rule: earliest release date (date de disponibilité) first. Rename them T1, …, Tn in that order.
  2. 2s1 := r1 ; C1 := s1 + p1The first task starts as soon as it arrives.
  3. 3for i := 2 to n doThen each next task in the sorted order.
  4. 4 si := max(C(i−1), ri)It starts when two things are true: the machine is free (Ci−1) and the task has arrived (ri). So take the later of the two. If ri is later, the machine waits: forced idle time (temps mort).
  5. 5 Ci := si + piIt ends after its duration.
  6. 6Cmax := CnThe end of the last task.

In simple terms: serve tasks in order of arrival. The machine then only waits when nothing at all has arrived, and no order can avoid that wait.

1|set-up|Cmax (temps de transition)

↑ contents
In plain words

Switching from one task to the next costs time (changing a tool, cleaning, adjusting). The work itself is fixed, so only the switches can be cut. Choosing the order is then a "visit every city once, shortest route" problem, which is hard. A greedy rule gives a good, not guaranteed, answer.

  • setup time (temps de transition, de réglage) cijTime needed between finishing Ti and starting Tj. Not symmetric: c13 = 2 but c31 = 1 below.
  • Hamiltonian path (chemin hamiltonien)A path through every vertex exactly once. Here: vertices = tasks, arc Ti→Tj weighted by cij.
  • greedy / nearest-neighbour heuristic (heuristique)Start with the cheapest arc, then always go to the cheapest next task.
Cmax = Σ pi + Σ (setup times along the sequence) → minimise the second sum
The heuristic, line by line (the course numbers the last line 10)
  1. 1choose (Ti, Tj), i ≠ j, with minimal cijLook at the whole table of setup times (temps de transition) cij and take the cheapest switch. Ti will go first, Tj second.
  2. 2si := 0 ; Cmax := pi + cijTi starts at 0. The running end time Cmax now counts Ti’s work plus the switch to Tj.
  3. 3T := T \ {Ti}Ti is done: remove it from the set T of tasks left.
  4. 4while |T| ≥ 2 doRepeat while at least two tasks are left (the current one Tj and at least one more).
  5. 5 choose Tk in T \ {Tj} with minimal cjkFrom the current task Tj, pick the cheapest next task Tk. It must not be Tj itself (cjj = 0 would always win).
  6. 6 sj := Cmax ; Cmax := Cmax + pj + cjkTj starts now; add its work and the switch to Tk.
  7. 7 T := T \ {Tj} ; j := kTj is done; Tk becomes the current task.
  8. 10sj := Cmax ; Cmax := sj + pjOnly one task is left: run it. No switch after the last task.

In simple terms: start with the cheapest switch in the table, then always go to the cheapest next task (nearest neighbour). Quick, but no guarantee.

1||Cw and 1||C (règles WSPT et SPT)

↑ contents
In plain words

Now every task counts, not just the last one. Short tasks first means many tasks finish early. With weights, compare "time it takes per unit of importance": the smaller pi/wi, the earlier the task goes.

  • weight (poids) wiHow important task Ti is.
  • mean completion time (temps moyen de fin)C = (Σ Ci) / n ; weighted: Cw = (Σ wiCi) / Σ wi.
  • SPT (Shortest Processing Time)Sort by increasing pi.
  • WSPT (Weighted SPT, règle de Smith)Sort so that p1/w1 ≤ p2/w2 ≤ … ≤ pn/wn.
Theorem 2. WSPT solves 1||Cw in O(n log n). Corollary 3. SPT solves 1||C (take all wi = 1).

Why (exchange argument): take two neighbours, Ti then Tj. Swapping them changes Σ wkCk by exactly wipj − wjpi, which is ≥ 0 when pi/wi ≤ pj/wj. So any order that breaks WSPT can be improved by a swap.

The rule, line by line
  1. 1compute pi / wi for every taskTime it takes per unit of importance (weight (poids) wi). Small = quick and important.
  2. 2sort so that p1/w1 ≤ p2/w2 ≤ … ≤ pn/wnWSPT rule (règle de Smith): smallest ratio first. With all wi = 1 this is SPT: shortest task first.
  3. 3run them in that order, no gap: Ci := C(i−1) + piSame as §2: each task starts when the previous ends.
  4. 4C̄w := (Σ wiCi) / (Σ wi)The weighted mean completion time (temps moyen pondéré).

In simple terms: if every task counts, finish the quick-and-important ones first, so many weights stop the clock early.

1|ri|C (dates de disponibilité, temps moyen)

↑ contents
In plain words

Add release dates to the SPT problem and it becomes hard (NP-hard). The usual heuristic: whenever the machine is free, run the shortest task that has already arrived. If nothing has arrived, jump to the next arrival.

  • available set (tâches disponibles) RTasks not yet done with ri ≤ t.
  • current time (instant courant) tWhen the machine becomes free.
  • dispatching rule (règle de priorité)Decide only when the machine is free, using what is available now. Never waits on purpose.
The heuristic, line by line (line 7 as corrected, see Notes)
  1. 1t := min ri ; som := 0Start the clock t at the first arrival. som will add up the completion times.
  2. 2R := {Ti in T : ri ≤ t}R = the available set (tâches disponibles): tasks not done that have already arrived.
  3. 3while |T| ≥ 1 doRepeat while tasks are left.
  4. 4 choose Tj in R with minimal pjAmong the arrived tasks, the shortest (SPT idea).
  5. 5 sj := t ; som := som + (sj + pj)Tj starts now; add its completion time to som.
  6. 6 T := T \ {Tj} ; R := R \ {Tj}Tj is done.
  7. 7 t := t + pj ; if R = ∅ then t := max(t, min ri over T)Move the clock to the end of Tj. Only if nobody is waiting, jump forward to the next arrival.
  8. 8 R := {Ti in T : ri ≤ t}Update who has arrived by now.
  9. 10C̄ := som / nMean completion time.

In simple terms: whenever the machine is free, run the shortest task that has already arrived; never wait on purpose. Hard problem (NP-hard), so this is only a rule of thumb.

1||Lmax and 1||Tmax (dates échues, règle EDD)

↑ contents
In plain words

Each task now has a promised date. Being late costs penalties and reputation, so we look at the worst delay. Do the most urgent task first: sorting by due date makes the worst lateness as small as possible.

  • due date (date échue) diThe date promised for Ti. Finishing later is allowed but penalised.
  • lateness (retard algébrique) Li = Ci − diNegative when the task is early.
  • tardiness (retard) Ti = max(0, Li)Only counts real delay.
  • EDD (Earliest Due Date, règle de Jackson)Sort tasks by increasing di.
Theorem 4. EDD solves 1||Lmax in O(n log n). Corollary 5. EDD also solves 1||Tmax, since Tmax = max(0, Lmax).

Why: if a task with a later due date runs just before one with an earlier due date, swapping them never increases the larger of their two latenesses.

The rule, line by line
  1. 1ranger les tâches suivant l’ordre croissant de leurs dates échuesThe course’s words: sort the tasks by increasing due date (date échue) di. This is EDD (Earliest Due Date).
  2. 2run them in that order, no gapAs in §2: Ci = Ci−1 + pi.
  3. 3Li := Ci − diLateness (retard algébrique) of each task: negative = early, positive = late.
  4. 4Lmax := max Li ; Tmax := max(0, Lmax)The worst lateness. Tardiness (retard) counts only real delay, so Tmax uses the same order (Corollary 5).

In simple terms: do the most urgent task first. Swapping a later-due task in front of an earlier-due one can never help the worst delay.

1|ri|Lmax (dates de disponibilité et dates échues)

↑ contents
In plain words

Mix arrivals and due dates and the problem becomes hard (NP-hard: no fast exact method is known): an urgent task may arrive just after you started a long one. Three special cases stay easy, because one of the two kinds of dates stops mattering.

  • all ri = rEverybody arrives together → EDD.
  • all di = dLmax = Cmax − d → minimise Cmax → ERD (sort by ri).
  • all pi = 1 (durées unitaires)At each time, run the available task with the smallest due date.
The three easy cases, one rule each
  1. ari = r pour tout iEverybody arrives together, so arrivals do not matter: use EDD (sort by di, §7).
  2. bdi = d pour tout iEverybody is due at the same date, so Lmax = Cmax − d: just finish as early as possible: sort by ri (ERD, §3).
  3. cpi = 1 pour tout iUnit tasks: at each instant, run the arrived task with the smallest due date.

In simple terms: in general 1|ri|Lmax is hard, but if one of the three kinds of data is the same for everybody, a simple sort works.

1||U: fewest late tasks (nombre de tâches en retard, algorithme de Moore)

↑ contents
In plain words

Sometimes only "late or not" matters. Go through the tasks by due date. When one would be late, throw out the longest task kept so far: it frees the most time for the others. Thrown-out tasks go at the end, in any order.

  • late indicator (indicateur de retard) Ui1 if Ci > di, else 0. Course criterion: U = (Σ Ui)/n.
  • on-time set (tâches non en retard) FTasks kept, run in EDD order. Late tasks: T \ F, so Σ Ui = n − |F|.
  • Moore's algorithm (Moore, 1968; Theorem 6)Solves 1||U in O(n log n).
The course’s algorithm, line by line
  1. 1ranger les tâches suivant la règle EDDSort by due date first.
  2. 2F := ∅ ; t := 0F = the on-time list (tâches non en retard), empty at the start. t = when the tasks of F end, back to back.
  3. 3pour i := 1 haut n faireFor i from 1 up to n (“haut” = counting up), in EDD order.
  4. 4 F := F ∪ {Ti} ; t := t + piTry keeping Ti: add it to F; the clock moves on by pi.
  5. 5 si t > di alorsIf Ti would now end after its due date…
  6. 6 trouver Tj de F ayant le plus long temps de traitement…find the longest task in F (it may be Ti itself),
  7. 7 F := F \ {Tj} ; t := t − pj…and drop it: it goes to the late pile. Its time is given back.
  8. 8–9 fsi … faitEnd of “if” (fsi) and of the loop (fait).
  9. resultF, puis T \ FRun F in EDD order, then the dropped tasks in any order. Number late = n − |F|.

In simple terms: go through tasks by due date. As soon as one would be late, throw out the longest task kept so far, because that frees the most time.

1|ri, d̃i|Cmax (dates limites, arborescence)

↑ contents
In plain words

A deadline is a hard wall: a task may not finish after it. The problem is hard, so we list the possible orders as a tree and cut every branch as soon as a task would miss its deadline. Depth-first search walks the tree.

  • deadline (date limite) d̃iMust hold: Ci ≤ d̃i. Unlike a due date, it cannot be broken.
  • search tree (arborescence de recherche)Level k fixes the k-th task. A node at level i has up to n − i children.
  • pruning (élagage)If Cj = max(Cprev, rj) + pj > d̃j, the node is dropped with its whole subtree.
  • depth-first search (parcours en profondeur d’abord)Go down one branch fully before trying the next.
The course’s method, step by step
  1. 1racine : aucune tâche affectéeThe root (racine): nothing scheduled yet.
  2. 2niveau 1 : nœud i = Ti en première positionLevel 1 has one node per task: “Ti goes first”, running from ri to ri + pi.
  3. 3un nœud du niveau i a n − i filsUnder a node, one child per task not yet scheduled: “this task goes next”.
  4. 4Cj := max{C, rj} + pjThe child’s end time: start when the machine is free (C of the parent) and the task has arrived (rj).
  5. 5si Cj > d̃j : le nœud n’est pas considéréDeadline (date limite) broken: cut this node and everything under it (pruning, élagage).
  6. 6parcours en profondeur d’abordDepth-first (en profondeur d’abord): always go down to a child before trying the next brother.
  7. 7meilleure feuilleEvery node at level n is a full valid order; keep the one with the smallest end time.

In simple terms: try orders one task at a time, and stop a branch as soon as it breaks a deadline. Exact, but slow for big n (the problem is NP-hard).

1|ri, qi|Cmax (temps de livraison, heuristique de Schrage)

↑ contents
In plain words

After the machine, each task still needs delivery time (like a fast-food order driven to a customer). Deliveries run in parallel, off the machine. The job is done when the last delivery arrives. Schrage's rule: among the tasks that have arrived, start the one with the longest delivery.

  • delivery (tail) time (temps de livraison, de finition) qiSecond phase after the machine; does not use the machine.
  • objectiveCmax = max (Ci + qi), the last delivery.
  • Schrage heuristic (Schrage, 1971)A heuristic (heuristique) is a quick rule of thumb: usually good, never guaranteed best. This one: Available task with the largest qi, ties broken by largest pi. The problem itself is hard.
The course’s heuristic, line by line
  1. 1t := min{ri}Start the clock at the first arrival.
  2. 2tantque T ≠ ∅ faireWhile (“tant que”) tasks are left.
  3. 3 T′ := {Ti ∈ T / ri ≤ t}T′ = tasks that have arrived by time t.
  4. 4 choisir Ti ∈ T′ : qi maximal, puis pi maximalAmong them, take the longest delivery time (temps de livraison) qi; if tied, the longest pi.
  5. 5–6 ordonnancer Ti à t ; Ci := t + piRun it now; it leaves the machine at Ci.
  6. 7 T := T \ {Ti}Done.
  7. 8 t := max{Ci, min{rl : Tl ∈ T}}Clock to the end of Ti; if nothing has arrived by then, jump to the next arrival.
  8. 9faitEnd of the loop.
  9. 10Cmax := max{Ci + qi}Each task reaches its customer at Ci + qi; the job is over at the last delivery.

In simple terms: whenever the machine is free, start the arrived task whose delivery takes longest, so the long trips leave early. Never wait on purpose.

12

1|prec|Cmax (contraintes de précédence)

↑ contents
In plain words

Some tasks can only start once other tasks are finished: you cannot paint a wall before it is built. These “first this, then that” rules are called precedence constraints. With one machine and every task ready at time 0, the machine never has to wait, so it always ends at the total work Σp, whatever the order. The only real job is to find some order that respects every rule.

The course builds that order from the end. A task that nothing has to follow can safely go last. Put it last, forget it, and repeat with the tasks that are left.

  • precedence constraint (contrainte de précédence) Ti < TjTj may start only after Ti has finished.
  • precedence graph (graphe de précédence)One circle per task, an arrow Ti → Tj for each rule.
  • direct successor / predecessor (successeur / prédécesseur immédiat)In Ti → Tj, Tj is a direct successor of Ti, and Ti a direct predecessor of Tj.
  • topological order (ordre topologique)A list of all tasks where every arrow points from left to right. Exactly the valid orders.
  • adjacency matrix (matrice d’adjacence) aijA table with aij = 1 when there is an arrow Ti → Tj, else 0. It is just the arrows written as a table.
  • ns(i) (nombre de successeurs)How many direct successors of Ti are still not placed. ns(i) = 0 means Ti may go last among what is left.
Theorem 7. This algorithm solves 1|prec|Cmax in O(n²), and Cmax = p1 + … + pn.
The course’s algorithm, line by line
  1. 1pour i := 1 haut n faire ns(i) := Σj aijFor each task, count its arrows going out: ns(i), the number of direct successors (successeurs immédiats). aij = 1 when there is an arrow Ti → Tj (adjacency matrix).
  2. 2S := TS = tasks not placed yet: all of them.
  3. 3pour k := n bas 1 faireFor k from n down to 1 (“bas” = counting down): fill positions from the last.
  4. 4 trouver Tj de S avec ns(j) = 0Find a task with nothing left that must come after it. It can safely go in position k. (Course: smallest number first.)
  5. 5 S := S \ {Tj} ; ns(j) := +∞ ; π(k) := jPlace it: π(k) = the task in position k. ns := +∞ so it is never picked again.
  6. 6 pour i … si aij = 1 alors ns(i) := ns(i) − 1Each task with an arrow into Tj now has one fewer successor waiting.
  7. 7faitEnd of the loop. π(1), …, π(n) is a topological order (ordre topologique).

In simple terms: the end time is always the total work, so we only need a valid order. Build it from the back: a task that nothing has to follow can go last.

13

1|prec, ri, pi = 1|Cmax (tâches unitaires, dates de disponibilité)

↑ contents
In plain words

Now every task lasts exactly 1, each has an arrival date, and the “first this, then that” rules still apply. Trick: if Ti must come before Tj, then Tj can never start before Ti has arrived and done its 1 unit. So raise Tj’s arrival date to at least ri + 1. After this, every arrow goes from a smaller date to a bigger one, and simply serving tasks by arrival (the ERD rule of §3) respects all the rules by itself.

  • unit tasks (tâches unitaires) pi = 1Every task takes one time unit.
  • release date (date de disponibilité) riTi cannot start before ri.
  • topological numbering (énumération topologique)Renumber the tasks so every arrow goes from a smaller to a bigger number: repeatedly take a task with no predecessor left. If at some point none is left, the arrows form a loop (circuit) and no valid order exists.
  • modified release date (date de disponibilité modifiée) r′jFor each arrow Ti → Tj, in that order: rj := max(rj, ri + 1).
  • block (bloc)A run of tasks done back to back, with no idle time inside. A new block starts each time the machine has to wait.
Theorem 8. Solved in O(n²) by three steps: (1) topological numbering, (2) modify the release dates, (3) sort by the new dates and run each task as early as possible. The procedure “blocs” of the course just does step 3 and records where the idle gaps are.
The course’s three procedures, line by line
  1. 1i := 1Énumération topologique (renumbering): start numbering at 1.
  2. 2tantque ∃ v sans prédécesseur faire α(v) := i ; supprimer v et ses arcs ; i := i + 1While some task v has no predecessor left: give it the next number α(v), delete it and its arrows, go on.
  3. 3si V ≠ ∅ alors circuitIf tasks remain but each still has a predecessor, the arrows form a loop (circuit): no valid order exists.
  4. 4pour i := 1 haut n−1, pour j := i+1 haut nModifier ri: look at every pair, in the new numbering.
  5. 5 si Ti < Tj (immédiat) alors rj := max{rj, ri + 1}If Ti → Tj, Tj cannot start before Ti arrives and runs its 1 unit: raise rj if needed.
  6. 6ranger par ordre croissant des nouvelles riBlocs: sort by the new release dates.
  7. 7t := r1 ; i := 1 ; j := 1 ; B1 := ∅Clock at the first arrival; first block B1 empty.
  8. 8tantque i ≤ n faireWhile tasks are left.
  9. 9 tantque ri ≤ t faire Bj := Bj ∪ {Ti} ; t := t + 1 ; i := i + 1The next task has arrived: run it now (1 unit), add it to the current block.
  10. 10 t := ri ; j := j + 1 ; Bj := ∅The next task has not arrived: the machine waits until ri, and a new block starts.

In simple terms: push every arrival date forward along the arrows, then serve tasks by arrival date. Each idle gap separates two blocks (blocs).

14

1|prec|Lmax (précédence et dates échues)

↑ contents
In plain words

Each task has a due date di (late is allowed but bad), and the “first this, then that” rules apply. If Tj is due at 4 and Ti must come before it, then Ti is really urgent too, whatever its own due date says. So first lower each task’s due date to the smallest due date of everything that has to follow it. Then, each time the machine is free, run the most urgent task whose predecessors are all done. Lateness is still measured with the real due dates.

  • lateness (retard algébrique) Li = Ci − diHow long after its due date Ti ends (negative if early). Lmax is the largest one.
  • modified due date (date échue modifiée) d*i = min(di, dj for every Tj after Ti)Compute it from the last task back to the first, using the already lowered d* of the successors.
  • ready task (tâche disponible)Not done yet, and all its predecessors are done.
Theorem 9. This solves 1|prec|Lmax in O(n²). The same algorithm solves 1|prec|Tmax (tardiness Ti = max(0, Li)).
The course’s algorithm, line by line
  1. 1d*i := min{di, min{dj / Ti < Tj}}Lower each due date to the smallest due date of the tasks that must come after it. Do it from the last task back to the first, using their already lowered d*.
  2. 2ordonnancer suivant l’ordre croissant des d*i en respectant les précédencesEach time the machine is free, among the ready tasks (disponibles) (all predecessors done) run the one with the smallest d*.

In simple terms: a task is as urgent as the most urgent task waiting behind it. Lateness is still measured with the real due dates di.

Why lower the due dates? A tiny case

T1 (p = 1, d = 10) → T3 (p = 1, d = 2), and T2 (p = 2, d = 5) with no arrow. At time 0 the ready tasks are T1 and T2. With the real dates you pick T2 (5 < 10): order T2, T1, T3, and T3 ends at 4, so Lmax = 4 − 2 = 2. With d*1 = min(10, 2) = 2 you pick T1: order T1, T3, T2, and Lmax = 0.

1|prec|U (nombre de tâches en retard, heuristique)

↑ contents
In plain words

Same setting as §14, but now we only count how many tasks are late. Moore’s trick of §9 (throw out the longest task) no longer works, because thrown-out tasks may be needed before others. The problem is hard (NP-hard), even when every task lasts 1. So the course gives a heuristic, a quick rule of thumb: each time the machine is free, among the ready tasks run the one with the smallest due date (if tied, the shortest), and note whether it is late.

  • late indicator (indicateur de retard) Ui1 if Ti ends after its due date (Ci > di), else 0. U = (U1 + … + Un) / n, the fraction of late tasks, as in §9.
  • heuristic (heuristique)Fast and usually decent, but no promise of the best answer. The example below shows it missing the best.
  • Theorem 10 (Théorème 10)1|prec, pi = 1|U is NP-hard: no fast exact method is known.
The course’s heuristic, line by line
  1. 1t := 0 ; ubar := 0Clock at 0; ubar will count tasks.
  2. 2tantque T ≠ ∅ faireWhile tasks are left.
  3. 3 T′ := {Ti ∈ T sans prédécesseur}Ready tasks: no predecessor left.
  4. 4 choisir Ti ∈ T′ : di minimal, puis pi minimalSmallest due date; if tied, the shortest.
  5. 5 ordonnancer Ti à l’instant tRun it now.
  6. 6 ui := 1 si t + pi ≤ di, 0 sinonAs written, ui = 1 means on time. This page counts late tasks instead (ui = 1 if t + pi > di), as in §9; see Notes.
  7. 7 ubar := ubar + uiAdd it to the count.
  8. 8–9 T := T \ {Ti} ; t := t + piDone; clock moves on.
  9. 11ubar := ubar / nThe fraction.

In simple terms: among the tasks allowed to start, always run the most urgent one, and count who ends late. Hard problem (NP-hard even with pi = 1), so no promise.

↑ contents
In plain words

The course ends with a table that sorts every one-machine problem into two piles. Left: a fast exact method is known (a sorting rule or a simple procedure). Right: NP-hard, no fast exact method is known, so you use a search tree (exact but slow) or a heuristic (fast but not always best). Often one extra constraint is enough to jump from left to right.

Notes on the original course
  • 1|ri|C heuristic, step 7. The course writes t := max{t + pj, minT\R ri}, which jumps the clock to the next release even when tasks are still waiting. Applied literally to Example 4 it gives T4 (0–1), T3 (5–7), T2 (7–10), T1 (10–15), so C = 33/4 = 8.25, not the 6 of the course figure. The jump should only happen when R is empty (corrected in §6).

  • Example 2. The course presents Cmax = 13 as the result without saying how the step 1 tie (four arcs of cost 1) is broken. Starting from (T1, T2) the heuristic gives 14. 13 is the true optimum (checked over all 24 orders).
  • Example 8 tree (part 2). The drawing leaves out four nodes that respect the deadlines: (T3, T1)/6, (T3, T2)/4, (T3, T2, T1)/6 and (T2, T3, T1)/6. They all die before level 4, so the answer is unchanged, but a full depth-first search does visit them (the live figure of §10 shows them).
  • Example 8 answer (part 2). The course gives “the” optimal sequence T4, T2, T3, T1. T4, T3, T2, T1 also ends at 7: the optimum is not unique.
  • Example numbers in part 3. Part 3 starts again at “Exemple 8” and “Exemple 9”, which part 2 already used. This page calls them 8′ and 9′.
  • Example 8′ (part 3), last line of the trace. The course writes π(1) = 2; it should be π(1) = 1 (T1 is the task picked at k = 1). The final order T1, T2, T3, T6, T5, T4 given by the course is right.
  • Procedure “blocs”. It writes Ci := t after i := i + 1, so the end time is stored on the next task instead of the one just run; it should come before the increment. The inner loop also needs the test i ≤ n, or it reads past the last task.
  • Example 10 figure. The time axis shows the tick “4” where T3 ends; T3 runs 2 → 5, so the tick should read 5. The Lmax line below it correctly uses 5 − 6.
  • 1|prec|U heuristic. The course sets ui = 1 when t + pi ≤ di, that is when the task is on time, so its ubar counts on-time tasks. Everywhere else (part 2) U counts late tasks; this page uses that meaning. The heading says 1|prec|U while Theorem 10 is about 1|prec, pi = 1|U, and the course gives no example (§15 uses Example 10’s data, where the heuristic finds 3 late tasks against an optimum of 2).
  • Notation. The course mixes separators: 1||Cmax, 1/set-up/Cmax, 1//Cw. All mean the same α|β|γ notation; this page uses “|” throughout.
